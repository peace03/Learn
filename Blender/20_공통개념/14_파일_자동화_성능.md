# 14. 파일을 옮기고 반복 작업을 줄이는 원리

먼저: [데이터와 관계](01_%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%99%80_%EA%B4%80%EA%B3%84.md). [재질](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#material) 교환은 [재질](06_%EC%9E%AC%EC%A7%88%EA%B3%BC_%EB%85%B8%EB%93%9C.md)도 읽습니다.

## 파일 하나와 작업 전체는 다르다

blend는 [Blender](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#blender) 작업을 저장하지만 외부 이미지·글꼴·[캐시](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/08_%EB%AC%BC%EB%A6%AC%EC%99%80%EC%8B%9C%EB%AE%AC%EB%A0%88%EC%9D%B4%EC%85%98.md#cache)·링크 [라이브러리](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#library)를 참조할 수 있습니다. [Relative Path](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#relative-path)는 현재 blend 위치를 기준으로, [Absolute Path](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#absolute-path)는 드라이브부터의 전체 위치로 다른 파일을 찾습니다. Blender의 `//`는 현재 blend 폴더 기준입니다.

[Pack Resources](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#pack)는 지원되는 외부 자료를 파일 안에 넣습니다. 모든 외부 자료를 무조건 내장하는 기능은 아닙니다. 작업을 전달할 때는 참조 자료와 저장 상태까지 확인합니다. [텍스처](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#texture)를 수정했다면 이미지 저장도 확인합니다.

[Append](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#append)는 다른 blend 자료를 현재 파일 안으로 가져오는 방식이고 [Link](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#link)는 외부 자료를 참조하는 방식입니다. [Library Override](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#library-override)는 링크한 자료의 허용된 일부를 [장면](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#scene)별로 바꿉니다. [Asset Browser](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#asset-browser)는 재사용 자료를 찾는 창이며, [가져오기](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#import) 방식에 따라 수정·공유 관계가 달라집니다.

### USD를 기초부터 이해하기

큰 장면은 부츠 메시 하나로 끝나지 않습니다. 캐릭터·집·조명·여러 사람의 변경을 함께 관리해야 합니다. USD는 이런 자료를 이름과 관계로 기록하고 **여러 자료를 조합해 한 장면으로 읽는 체계**입니다. [OpenUSD 공식 개요](https://openusd.org/release/), [공식 FAQ](https://openusd.org/release/usdfaq.html).

Prim은 장면 속 이름 있는 구성 요소입니다. Layer는 장면 정보나 변경을 담는 단위이고, Stage는 여러 자료를 조합해 현재 읽는 장면 상태입니다. 예를 들어 원본 부츠 자료와 ‘이 장면에서는 X 양수에 배치’라는 변경을 [분리](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/03_%EB%A9%94%EC%8B%9C%EC%99%80%EB%AA%A8%EB%8D%B8%EB%A7%81.md#separate)해 관리할 수 있습니다. 이것은 원리를 이해하기 위한 예이며 현재 Blender 파일이 그런 USD 구조라는 뜻은 아닙니다. [OpenUSD 용어](https://openusd.org/release/glossary.html).

[USDZ](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#usdz)는 관련 자료를 묶기 위한 [패키지](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#package) 형태입니다. 파일이 묶였다고 모든 프로그램의 재질·물리·리그가 동일해지지는 않습니다. [USDZ 규격](https://openusd.org/release/spec_usdz.html).

## Unity로 전달할 때 구분할 검사

1. Blender 안에서 원본과 내보낼 대상을 확인합니다.
2. 형식이 필요한 메시·UV·재질 자료·뼈·애니메이션을 지원하는지 확인합니다.
3. 내보낸 파일을 목적 프로그램에서 읽습니다.
4. 크기·방향·면·텍스처·뼈 움직임을 실제로 확인합니다.

내보내기 성공은 2~4의 모든 성공을 뜻하지 않습니다. Blender [노드](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#node) 전체를 [Unity](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#unity) [셰이더](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#shader)가 이해하지 못할 수 있으므로 지원되는 자료로 [변환](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/02_%EC%A2%8C%ED%91%9C%EC%99%80%EB%B3%80%ED%99%98.md#transform)하거나 목적 엔진에서 다시 구성합니다. 이번 부츠 설명서에서는 내보내기를 실행하지 않았습니다.

## 자동화와 성능은 측정할 대상부터 정한다

[Python](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#python)과 [bpy](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#bpy) [API](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#api)는 반복 이름 변경·자료 검사·생성에 쓰입니다. bpy.[data](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#data)는 저장 자료, bpy.[context](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#context)는 현재 창·[선택](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#selection) 상태, bpy.ops는 명령 호출을 다루는 대표 접근점입니다. [UI](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#ui) 명령 자동화는 [모드](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#mode)·선택 문맥에 의존할 수 있으므로 대상 이름과 변경 범위를 확인합니다. [Add-on](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#addon)과 [Extension](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#extension)은 추가 기능을 배포·설치하는 방식이며 기본 기능과 버전 호환성을 구분합니다.

느리다는 이유만으로 모든 면을 줄이지 않습니다. [모디파이어](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#modifier) 계산은 [CPU](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#cpu), 렌더는 선택한 엔진·CPU/[GPU](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#gpu), 큰 자료는 [RAM](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#ram)/[VRAM](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#vram), 캐시는 저장 장치에 영향을 줄 수 있습니다. [프로파일링](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/10_%ED%8C%8C%EC%9D%BC%EC%9E%90%EB%8F%99%ED%99%94%EC%84%B1%EB%8A%A5.md#profiling)은 실제 시간·메모리가 쓰인 곳을 측정하는 일입니다. 표면을 줄인 뒤 [실루엣](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/03_%EB%A9%94%EC%8B%9C%EC%99%80%EB%AA%A8%EB%8D%B8%EB%A7%81.md#silhouette)·UV·관절이 망가지면 목표를 달성한 것이 아닙니다.

확인 질문: **가벼워진 파일을 저장했으니 최적화 완료인가?** 답: 필요한 외형·변형·실행 성능까지 확인해야 합니다. 파일 크기 감소와 실제 재생 속도 향상은 같은 지표가 아닙니다.
