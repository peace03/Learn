# 08. 장면이 픽셀 이미지가 되는 과정

먼저: [UV](05_UV와_텍스처.md), [재질](06_재질과_노드.md), [조명](07_조명과_카메라.md).

[렌더링](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#render)은 [장면](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#scene)을 화면의 색칸으로 계산하는 과정입니다. 대략 **어느 표면이 보이는가 → 그 표면에 어떤 빛이 오는가 → [카메라](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#camera)에 얼마가 돌아오는가 → 표시 가능한 색으로 어떻게 보여 줄까**를 계산합니다.

## 엔진은 계산 방법이 다르다

[EEVEE](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#eevee)는 빠른 확인에 맞는 [래스터화](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#rasterization) 기반의 계산과 여러 조명 방법을 조합합니다. [Cycles](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#cycles)는 빛 경로를 [표본](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#sample)으로 [추적](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/09_2D%ED%95%A9%EC%84%B1%EA%B3%BC%EC%98%81%EC%83%81.md#tracking)하는 [패스 트레이싱](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#path-tracing)을 사용합니다. [Workbench](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#workbench)는 모양·배치 확인에 맞습니다. ‘같은 [Blender](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#blender)니까 결과가 같아야 한다’고 생각하지 않습니다. [공식 렌더 개요](https://docs.blender.org/manual/en/5.0/render/introduction.html), [EEVEE](https://docs.blender.org/manual/nl/5.2/render/eevee/index.html), [Cycles](https://docs.blender.org/manual/en/5.0/render/cycles/introduction.html).

Cycles는 모든 가능한 빛 경로를 한 번에 다 계산하지 않고 여러 경로의 결과로 추정합니다. 표본이 적으면 점 같은 밝기 차이가 남습니다. 샘플을 늘리면 대체로 줄지만 시간이 늘어납니다. [Denoise](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#denoise)는 주변 정보를 이용해 [노이즈](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#noise)를 줄이므로 작은 장식까지 지워지지 않았는지 봅니다.

## 색 숫자는 해석 규칙이 필요하다

[RGB](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#rgb)는 빨강·초록·파랑 값의 묶음입니다. 하지만 같은 값이라도 [색 공간](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#color-space)이 다르면 같은 빛을 뜻하지 않을 수 있습니다. 일반 색 이미지의 [sRGB](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#srgb) 해석, 계산용 [Scene Linear](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#linear), 최종 [View Transform](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#view-transform)을 나누어 봅니다.

선형 빛 값에서는 0.2만큼의 빛 두 개를 더해 0.4로 계산하는 식의 관계가 성립합니다. 일반 저장 사진의 숫자는 사람 눈과 저장 효율 등을 고려한 [변환](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/02_%EC%A2%8C%ED%91%9C%EC%99%80%EB%B3%80%ED%99%98.md#transform)이 [적용](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#apply)되어 있어 그대로 더하는 것이 같은 계산은 아닙니다. [노멀 맵](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#normal-map)처럼 색이 아닌 숫자 자료는 [Non-Color](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#non-color)로 읽어 수의 의미를 유지합니다.

계산된 아주 밝은 값을 모니터에 보여 줄 때 View Transform이 작용합니다. [AgX](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#agx) 같은 방식은 넓은 밝기 범위를 표현하도록 조정합니다. 화면에서 보이는 색을 [텍스처](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#texture) 파일의 원래 수와 무조건 일치시키려 하면 조명·색 관리가 뒤섞입니다. Blender의 색 관리는 [OpenColorIO](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#ocio)를 사용합니다. [공식 Color Management](https://docs.blender.org/manual/en/4.4/render/color_management.html).

## 원인을 한 단계씩 나눠 확인한다

| 관찰 | 먼저 나눌 원인 |
|---|---|
| 작은 점 얼룩 | 샘플 부족인지 텍스처 무늬인지 |
| 화면 전체가 너무 밝음 | [광원](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#light)·[노출](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#exposure)·뷰 변환 중 어디가 바뀌었는지 |
| [모서리](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/03_%EB%A9%94%EC%8B%9C%EC%99%80%EB%AA%A8%EB%8D%B8%EB%A7%81.md#edge)에 계단 | 출력 [해상도](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#resolution)와 [안티앨리어싱](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#anti-aliasing) |
| 프로그램마다 다른 색 | 입력 색 공간·조명·출력 뷰 변환 |
| 모양만 보고 싶음 | 복잡한 [재질](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/04_UV%EC%99%80%EC%9E%AC%EC%A7%88.md#material)보다 Workbench/[Solid](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/01_%ED%99%94%EB%A9%B4%EA%B3%BC%EB%8D%B0%EC%9D%B4%ED%84%B0.md#solid)가 적절한지 |

[Render Pass](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#render-pass)는 [그림자](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#shadow)·깊이 등 결과 성분을 따로 뽑은 것입니다. [View Layer](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/05_%EC%A1%B0%EB%AA%85%EB%A0%8C%EB%8D%94%EC%83%89.md#view-layer)는 어떤 장면 구성과 패스를 계산할지 정합니다. 이 [분리](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/03_%EB%A9%94%EC%8B%9C%EC%99%80%EB%AA%A8%EB%8D%B8%EB%A7%81.md#separate)는 [합성](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/09_2D%ED%95%A9%EC%84%B1%EA%B3%BC%EC%98%81%EC%83%81.md#compositor)에서 특정 성분만 조정하는 데 도움이 됩니다. [공식 패스 설명](https://docs.blender.org/manual/en/latest/render/layers/passes.html).

확인 질문: **샘플을 열 배 늘리면 뒤집힌 [법선](../90_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84/03_%EB%A9%94%EC%8B%9C%EC%99%80%EB%AA%A8%EB%8D%B8%EB%A7%81.md#normal)이 고쳐지는가?** 답: 아닙니다. 같은 잘못된 표면 방향을 더 많이 계산할 뿐입니다.
