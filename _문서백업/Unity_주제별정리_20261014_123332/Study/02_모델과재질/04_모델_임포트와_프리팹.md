# 04. 모델 임포트와 프리팹

> 모르는 단어는 [전문 용어 전체 색인](../90_%EC%B0%B8%EA%B3%A0/%EC%9A%A9%EC%96%B4_%EC%82%AC%EC%A0%84.md)에서 영문·한글로 찾습니다. 이 장 맨 아래에는 등장 용어의 바로가기 목록이 있습니다.

## 먼저: 저장 규칙을 읽는 도구가 필요하다

준비 A의 확장자·참조, 준비 B의 메시·정점을 알아야 합니다. **모델**은 모양과 부속 정보를 담는 자료, **임포트**는 외부 파일을 Unity가 사용할 자료로 읽는 과정입니다. **프리팹**은 여러 컴포넌트와 자식 구성을 다시 쓰기 위해 저장한 에셋입니다. 같은 프리팹을 배치한 물체 각각이 **인스턴스**입니다.

아래 표의 USD는 3D 장면의 구성과 속성을 기록·합치는 체계입니다. USDZ는 그 장면과 관련 파일을 묶는 형식입니다. 이 장 다음 [04A. USD를 처음부터 이해하기](04A_USD를_처음부터_이해하기.md)에서 USD·USDA·USDC·USDZ를 따로 배우고 실제 원본 내부를 읽습니다.

FBX를 Project에서 클릭했을 때의 Model/Rig/Animation 탭은 **파일 읽기 설정**입니다. 같은 모델을 Hierarchy에서 클릭했을 때의 Transform/Animator는 **배치한 인스턴스 설정**입니다. 원하는 탭이 없으면 클릭한 창과 대상을 먼저 확인합니다.

## 파일과 씬 물체는 다르다

Project 창의 모델은 창고에 있는 설계도입니다. Hierarchy의 모델은 설계도로 만든 한 물체입니다. 설계도 하나로 씬에 여러 물체를 놓을 수 있습니다.

| 형식 | 담는 내용 | 이 프로젝트의 예 |
|---|---|---|
| `.fbx` | 메시·뼈·애니메이션 등 교환 데이터 | `Streetwear Robot_Walk.fbx` |
| `.usdz` | USD 장면과 이미지 등을 묶은 패키지 | Bridge로 받은 Walk 원본 |
| `.mat` | 셰이더와 속성·텍스처 참조 | `Streetwear Robot_Walk_Mat.mat` |
| `.prefab` | 다시 쓸 오브젝트 구성 | `Lab_Studio_Env.prefab` |
| `.controller` | Animator 상태와 전환 | Walk 재생 규칙 |
| `.anim` | 시간에 따른 값 변화 | 원본 보존·정리 클립 |
| `.meta` | Unity가 에셋을 구별하는 GUID와 임포트 설정 | FBX의 Rig 설정도 포함 |

FBX가 항상 텍스처를 포함하는 것은 아닙니다. 텍스처가 별도 파일인지, 내장인지, 연결이 끊어졌는지 구분합니다.

## 임포트의 원리

```text
원본 FBX + .meta 설정 → Unity Importer → 메시·재질·Avatar·Clip 같은 하위 에셋
```

**Importer**는 외부 파일을 Unity가 사용하는 데이터로 바꾸는 도구입니다. Inspector의 `Apply`는 현재 선택한 임포트 설정으로 다시 읽으라는 뜻입니다. 씬을 저장하는 `Ctrl+S`와 역할이 다릅니다.

`.meta`의 GUID는 파일의 이름표입니다. 이름을 바꾸거나 이동할 때 Project 창을 사용하면 참조 유지에 유리합니다. 파일 탐색기에서 원본만 옮기고 `.meta`를 빼놓으면 Unity가 다른 에셋으로 받아들일 수 있습니다.

## 실습 A: 준비된 프리팹 배치

1. `Study_Lab`을 엽니다.
2. Project에서 `Assets/VARCO_URP/01.Varco3D/Models/Classical Goddess Statue/Prefabs`를 엽니다.
3. `Classical Goddess Statue.prefab`을 **Hierarchy 빈 공간**에 드래그합니다. 기존 물체 이름에 놓으면 자식이 될 수 있습니다.
4. 새 인스턴스 이름을 `Study_Statue`로 바꿉니다.
5. `F`로 보고 위치·크기를 조절합니다. 가져온 모델마다 Pivot·원래 크기가 달라 “Y=0이면 발이 닿는다”는 보장은 없습니다.
6. Inspector의 Renderer가 보이지 않으면 Hierarchy 왼쪽 삼각형으로 자식을 펼쳐 메시가 있는 물체를 선택합니다.
7. 씬을 저장합니다.

이 과정은 프리팹 인스턴스 하나를 배치합니다. Prefab Mode에서 원본을 편집한 것이 아닙니다.

## 실습 B: 자기 프리팹 만들기

1. 03장에서 만든 `Study_Root`를 선택합니다.
2. Hierarchy의 `Study_Root`를 Project의 `_Study/Prefabs` 빈 공간으로 드래그합니다.
3. 새 `.prefab` 파일을 확인합니다.
4. 그 파일을 Hierarchy 빈 공간으로 두 번 드래그해 인스턴스 두 개를 만듭니다.
5. 한 인스턴스의 위치를 바꿉니다. 다른 인스턴스 위치는 그대로인지 확인합니다.

**Override**는 인스턴스에서 원본과 다르게 바꾼 값입니다. `Overrides > Apply`는 변경을 프리팹 원본으로 보내 다른 인스턴스에도 영향을 줄 수 있습니다. 공부 중 만든 차이를 남기려면 무엇을 적용하는지 먼저 확인합니다.

## 직접 FBX 설정 보기

Project에서 FBX 파일을 클릭하면 보통 `Model`, `Rig`, `Animation`, `Materials` 탭이 나옵니다.

| 탭 | 먼저 확인할 것 |
|---|---|
| Model | Scale Factor, 단위, 축, Normals·Tangents |
| Rig | Generic/Humanoid, Avatar 생성 방식 |
| Animation | Import Animation, 클립 범위, Loop Time |
| Materials | 재질 임포트와 외부 재질 연결 |

법선(Normal)은 면이 바라보는 방향입니다. 탄젠트(Tangent)는 표면을 따라가는 기준 방향이며 Normal Map 해석에 쓰입니다. 법선맵 문제를 색상맵 교체로 고칠 수 없는 이유입니다.

## 확인할 함정

- Walk 변환 프리팹 파일이 있다는 사실은 Controller가 연결되어 자동 재생된다는 뜻이 아닙니다. 이 프로젝트의 주 씬은 Walk FBX 인스턴스에 Animator를 추가해 씁니다.
- `Lab_Studio_Env` 프리팹 원본의 Volume Profile 참조 하나는 현재 파일 목록에서 해석되지 않습니다. 주 씬은 Override로 실제 `Lab_Studio.asset`을 연결합니다. 새 씬에 프리팹만 놓았다면 Volume의 `Profile`을 따로 확인합니다.
- 재질을 Renderer 슬롯에 넣을 때는 **Project의 `.mat` 파일을 끌어다가 Inspector > Renderer > Materials > Element 슬롯에 놓습니다.** 부모 Transform에 드래그하는 일이 아닙니다.

**확인 질문:** 프리팹 인스턴스의 위치 변경과 프리팹 원본 변경의 차이는? FBX 파일만 복사하면 색과 움직임 연결이 모두 따라오는가?

**답:** 전자는 씬의 해당 물체에, 후자는 원본을 쓰는 인스턴스들에 영향을 줄 수 있습니다. 별도 재질·텍스처·Controller와 참조를 확인해야 합니다.
