# Cloth 설정과 문제 해결

**고정부 → 이동 범위 → 중력·움직임 → 충돌체 → 계산 품질** 순서로 확인합니다. 앞의 연결이 빠졌다면 뒤의 품질 값을 올려도 해결되지 않습니다.

## Inspector에서 무엇을 바꾸나요?

설정 이름을 누르면 뜻과 예가 있는 사전 항목으로 이동합니다. 표의 ‘늘리면’은 일반적인 경향이며 모델마다 결과가 달라집니다.

| 설정 | 조정할 때 | 값을 키우거나 켜면 |
|---|---|---|
| [Stretching Stiffness](../../../90_참고/용어사전/11_Cloth와_천물리.md#stretching) | 천이 고무처럼 늘어남 | 길이 변화에 더 저항. 범위는 0보다 크고 1 이하 |
| [Bending Stiffness](../../../90_참고/용어사전/11_Cloth와_천물리.md#bending) | 너무 쉽게 접히거나 너무 뻣뻣함 | 접힘에 더 저항. 0~1, 0은 이 저항을 끔 |
| [Use Tethers](../../../90_참고/용어사전/11_Cloth와_천물리.md#tethers) | 고정부에서 멀리 늘어짐 | 고정된 점을 기준으로 과도한 늘어짐을 줄임 |
| [Use Gravity](../../../90_참고/용어사전/11_Cloth와_천물리.md#use-gravity) | 천을 아래로 처지게 함 | 중력이 작용. 고정된 점은 여전히 기준점을 따름 |
| [Damping](../../../90_참고/용어사전/11_Cloth와_천물리.md#damping) | 흔들림이 오래 남음 | 움직임이 더 빨리 잦아듦. 범위 0~1 |
| [External Acceleration](../../../90_참고/용어사전/11_Cloth와_천물리.md#external) | 한 방향으로 계속 밀기 | X·Y·Z로 지정한 방향의 가속도가 커짐 |
| [Random Acceleration](../../../90_참고/용어사전/11_Cloth와_천물리.md#random) | 불규칙한 흔들림 추가 | 방향별 무작위 가속도가 커짐 |
| [World Velocity Scale](../../../90_참고/용어사전/11_Cloth와_천물리.md#world-velocity) | 캐릭터의 이동 영향 조절 | 세계 좌표에서 움직이는 영향의 비율을 조정 |
| [World Acceleration Scale](../../../90_참고/용어사전/11_Cloth와_천물리.md#world-acceleration) | 출발·정지·방향 전환 영향 조절 | 캐릭터의 가속이 천에 미치는 비율을 조정 |
| [Friction](../../../90_참고/용어사전/11_Cloth와_천물리.md#friction) | 몸 표면에서 너무 미끄러짐 | 접촉 시 미끄러짐에 더 저항 |
| [Collision Mass Scale](../../../90_참고/용어사전/11_Cloth와_천물리.md#collision-mass) | 충돌 반응 세부 조정 | 충돌 중인 입자의 질량 배율을 조정. 옷 전체 무게 설정이 아님 |
| [Use Continuous Collision](../../../90_참고/용어사전/11_Cloth와_천물리.md#continuous) | 빠른 움직임에서만 뚫림 | 이동 경로까지 검사. 계산 비용 증가 |
| [Use Virtual Particles](../../../90_참고/용어사전/11_Cloth와_천물리.md#virtual) | 큰 삼각형 사이의 충돌 보완 | 삼각형 안의 추가 지점에서 충돌을 검사 |
| [Solver Frequency](../../../90_참고/용어사전/11_Cloth와_천물리.md#solver-frequency) | 기본 설정 이후 정확도 조절 | 반복 계산 수와 비용 증가 |
| [Sleep Threshold](../../../90_참고/용어사전/11_Cloth와_천물리.md#sleep) | 매우 작은 움직임의 정지 판정 | 쉬는 상태로 판단하는 속도 기준을 조정 |
| [Capsule Colliders](../../../90_참고/용어사전/11_Cloth와_천물리.md#capsule-list) | 팔다리·몸통 충돌 연결 | 목록에 넣은 캡슐이 충돌 대상이 됨 |
| [Sphere Colliders](../../../90_참고/용어사전/11_Cloth와_천물리.md#sphere-list) | 구 또는 굵기가 변하는 캡슐 연결 | First/Second에 연결한 구로 충돌 모양을 정함 |

최초 시험에서는 고급 항목을 한꺼번에 바꾸지 않습니다. **World Velocity/Acceleration Scale**은 중력 크기나 모델의 Transform Scale이 아닙니다. [이동 영향](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-worldVelocityScale.html), [가속 영향](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-worldAccelerationScale.html)

`Use Continuous Collision`의 API 이름은 `Cloth.enableContinuousCollision`입니다. `useContinuousCollision`이라고 추측해 쓰지 않습니다. [연속 충돌](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-enableContinuousCollision.html)

## 칠하기 도구에서 무엇을 바꾸나요?

| 항목 | 역할 | 주의할 점 |
|---|---|---|
| Select | 고른 점에 같은 값을 입력 | 입력 즉시 선택된 점들이 함께 바뀜 |
| Paint | 브러시로 지나간 점에 값을 입력 | 브러시 활성화 버튼과 값 사용 체크를 구별 |
| Gradient Tool | 선택한 점에 화면 왼쪽→오른쪽으로 값을 변화시킴 | Scene의 2D에서 사용. 몸 위→아래라고 자동 해석하지 않음 |
| Max Distance | 기준 위치에서 움직일 최대 거리 | 체크를 켠 0이 고정 |
| Surface Penetration | 기준 표면 뒤쪽의 침투 제한 | 별도 Body 전체의 충돌 검사와 다름 |
| Manipulate Backfaces | 가려진 뒷면 점도 조작 | 앞만 수정할 때 켜 두면 뒤도 바뀔 수 있음 |
| Brush Radius | 칠하는 붓의 범위 | 넓히면 원하지 않는 점도 칠할 수 있음 |
| Constraint Size | 화면에 표시하는 점 크기 | 천 두께·충돌 반지름은 바뀌지 않음 |

Paint에는 **칠할 속성을 고르는 작은 붓 버튼**과 **그 속성의 제한을 사용할지 정하는 체크**가 따로 있습니다. 먼저 Select로 소수의 점을 골라 값을 확인한 뒤 Paint를 쓰면 실수를 줄일 수 있습니다. 색 범례의 범위도 함께 봅니다. [Cloth Inspector의 Paint/Select 구현](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.6.0f1/Modules/ClothEditor/ClothInspector.cs)

## 자기 충돌은 필요할 때 추가합니다

**Self-Collision, 자기 충돌**은 한 Cloth 안에서 서로 다른 부분이 겹치는 것을 줄입니다. **Inter-Collision, 천 사이 충돌**은 서로 다른 Cloth 사이의 입자 충돌입니다. 몸의 Capsule Collider와 충돌하는 기능과는 별개입니다.

자기 충돌 설정 순서:

1. Play 정지 → 옷 선택 → Cloth의 **Edit Collision Particles** 버튼을 누릅니다. 아이콘 설명은 **Edit cloth self/inter-collision**입니다.
2. Scene의 **Cloth Self-Collision and Inter-Collision** 도구판에서 **Select**를 누릅니다.
3. 자기 충돌이 필요한 점들을 사각형으로 고릅니다. **Self-Collision and Inter-Collision** 체크를 켭니다.
4. Cloth Inspector의 **Self-Collision Distance**에 작은 양수, **Self-Collision Stiffness**에 0보다 큰 값을 입력합니다.
5. 저장하고 같은 동작으로 켜기 전·후를 비교합니다.

Distance는 입자 사이에 확보하려는 간격입니다. 예를 들어 가장 가까운 대상 점 사이가 0.02 단위라면 0.005처럼 더 작은 거리부터 시험할 수 있습니다. **원래 점 간격보다 크게 정하면**, 원래 모양을 유지하려는 제약과 서로 밀어내려는 제약이 충돌해 떨릴 수 있습니다. [selfCollisionDistance](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-selfCollisionDistance.html), [selfCollisionStiffness](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-selfCollisionStiffness.html)

다른 Cloth끼리 충돌시키려면 **양쪽 Cloth에서 위의 1~3번으로 대상 점을 고른 뒤**, **Edit > Project Settings > Physics > Cloth** 탭에서 **Enable Inter-Collision**을 켭니다. **Inter-Collision Distance**는 가장 가까운 대상 점 간격보다 작게, **Inter-Collision Stiffness**는 0보다 크게 두고 비교합니다. 이 설정은 프로젝트의 Cloth끼리 충돌하는 조건에 영향을 줍니다. 같은 Cloth의 Self-Collision 값을 올리는 것만으로 끝나지 않습니다. `Physics.interCollisionDistance`는 **서로 다른 Cloth** 입자의 최소 간격입니다. [API 정의](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Physics-interCollisionDistance.html), [6000.6.0f1 Physics 설정 UI](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.6.0f1/Modules/PhysicsEditor/PhysicsManagerInspector.cs)

공식 Manual 일부 문장에는 자기 충돌 설명 안에 `Inter-Collision Distance`라는 이름이 섞여 있습니다. 이 자료는 **6000.6.0f1 Inspector 소스의 `Self-Collision Distance / Stiffness`**를 따릅니다. 화면에서 실제로 표시되는 이름을 확인합니다.

## 증상별 확인 순서

| 증상 | 먼저 확인할 것 | 그다음 행동 |
|---|---|---|
| 점이 전부 안 보임 | 옷의 Mesh가 None인지, 다른 물체를 골랐는지, 편집 버튼이 켜졌는지 | 올바른 옷 하나를 선택하고 Cloth Constraints 도구판 열기 |
| 숫자 입력칸이 회색 | 점 선택 여부와 해당 제한의 체크 | Select에서 점 선택 후 체크 켜기 |
| 천 전체가 떨어짐 | 0으로 고정된 점이 실제로 있는지 | 위쪽·허리 등 연결부를 체크 켠 0으로 지정 |
| 중력을 켰는데 안 움직임 | Cloth 활성화, 모든 Max Distance가 0인지, Physics > Cloth의 Gravity Override | 끝부분에 작은 양수를 주고 외부 가속도로 비교 |
| 애니메이션부터 옷이 잘못 움직임 | Cloth를 끈 상태의 뼈 연결·가중치·기준 자세 | 스키닝 문제부터 수정 |
| 몸에서 옷이 너무 멀리 뜸 | Max Distance가 과한지, 충돌체가 너무 큰지 | 값을 줄이거나 충돌체 크기를 몸에 맞춤 |
| 몸을 그대로 통과함 | 지원하는 구·캡슐인가, 목록에 등록했는가, 몸을 따라가는가 | 목록·부위·크기부터 고침 |
| 바닥의 Box/Mesh Collider를 통과함 | 일반 충돌체를 Cloth가 자동 인식한다고 가정했는지 | 용도에 맞는 지원 충돌 모양을 설계. 바닥 메시 등록으로 해결되지 않음 |
| 빠르게 달릴 때만 뚫림 | 기본 충돌 배치가 맞는지 | Continuous Collision, Virtual Particles, Solver Frequency를 하나씩 비교 |
| 시작하자마자 튀거나 떨림 | 천·충돌체가 처음부터 겹쳤는지, 자기 충돌 거리가 너무 큰지 | 초기 겹침과 충돌 간격부터 줄임 |
| 앞쪽은 움직이고 뒤쪽은 뻣뻣함 | 가려진 점의 Max Distance | 뒤에서 점을 선택하거나 Manipulate Backfaces로 확인 |
| 한쪽 면이 사라짐 | 재질이 Front만 그리는지 | 연습용 URP 재질의 Render Face를 Both로 변경 |
| 카메라 밖에 갔다 오면 이상함 | Skinned Mesh Renderer의 Bounds와 Update When Offscreen | 경계·화면 밖 갱신 조건을 확인하고 비용도 함께 비교 |
| 저장한 줄 알았는데 값이 돌아감 | Play 중에만 변경했는지 | 정지 후 다시 입력·저장·재실행 |
| Wind Zone을 넣었는데 천이 안 흔들림 | Cloth에 가속도를 설정했는지 | External/Random Acceleration으로 먼저 확인 |

Wind Zone의 기본 설명 대상은 나무와 파티클 계통입니다. 이 실습에서는 Cloth의 가속도로 바람을 표현합니다. [Wind Zone](https://docs.unity3d.com/6000.6/Documentation/Manual/class-WindZone.html)

가상 입자는 충돌 검사를 보완하는 점입니다. **그림용 메시의 점이 늘거나 주름 해상도가 높아지는 것은 아닙니다.** [Virtual Particles](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-useVirtualParticles.html)

## 작업을 적용하는 순서

망토 한 벌에서 먼저 성공시킨 뒤 소매·치마로 넓힙니다. 부위마다 **어디를 붙잡는지, 무엇에 부딪히는지, 얼마나 움직여야 하는지**가 달라집니다. 표의 값을 복사하는 것보다 이 세 조건을 다시 정하는 것이 중요합니다.

성능이 나쁘면 점 수, Cloth 개수, 자기 충돌 대상, 충돌체 수, 반복 계산 수를 확인합니다. 한 번에 한 조건만 줄이고 실제 동작과 비용을 비교합니다. Cloth를 끄면 일반적으로 스키닝 중심의 모습으로 돌아가므로, 멀리 있는 캐릭터에서 끄는 방식도 외관을 확인한 뒤 판단합니다. 이 문서는 성능 측정값이나 특정 기기의 실행 보장을 제공하지 않습니다.

기본 설정의 정확한 의미는 [Cloth API](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth.html), 성능 확인 방법은 [18장](../../../06_활용과점검/18_성능과_빌드.md)에서 이어 읽습니다.
