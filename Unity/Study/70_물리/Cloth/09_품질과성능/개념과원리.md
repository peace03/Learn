## 정확도에는 계산 시간이 필요합니다

여러 제약을 한 번에 완벽하게 맞추기는 어렵습니다. 계산을 되풀이하며 오차를 줄이는 부분을 **Solver, 솔버**라고 합니다. **Solver Frequency**는 초당 반복 계산 수입니다. 화면을 그리는 횟수인 FPS와는 다른 값입니다.

예를 들어 공식 API 설명에서 240회/초는 60FPS일 때 프레임당 약 4회 계산하는 경우에 해당합니다. 값을 올리면 더 정확해질 수 있지만 계산 시간도 늘어납니다. 프레임 속도가 달라지거나 다른 조건이 바뀌면 결과를 다시 확인해야 합니다. [Cloth.clothSolverFrequency](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth-clothSolverFrequency.html)

이 때문에 점 수·충돌체·자기 충돌을 모두 최대치로 늘리는 방식보다 **필요한 부분에만 Cloth를 적용하고 같은 동작으로 비교**하는 것이 좋습니다. 성능이 충분한지는 실제 게임과 목표 기기에서 측정합니다.

## 관련 설정

설정 이름을 누르면 뜻과 예가 있는 사전 항목으로 이동합니다. 표의 변화는 일반적인 경향이며 모델마다 결과가 달라집니다.

| 설정 | 조정할 때 | 값을 키우거나 켜면 |
|---|---|---|
| [Solver Frequency](../90_용어사전.md#solver-frequency) | 기본 설정 이후 정확도 조절 | 반복 계산 수와 비용 증가 |
| [Sleep Threshold](../90_용어사전.md#sleep) | 매우 작은 움직임의 정지 판정 | 쉬는 상태로 판단하는 속도 기준을 조정 |

## 작업을 적용하는 순서

망토 한 벌에서 먼저 성공시킨 뒤 소매·치마로 넓힙니다. 부위마다 **어디를 붙잡는지, 무엇에 부딪히는지, 얼마나 움직여야 하는지**가 달라집니다. 표의 값을 복사하는 것보다 이 세 조건을 다시 정하는 것이 중요합니다.

성능이 나쁘면 점 수, Cloth 개수, 자기 충돌 대상, 충돌체 수, 반복 계산 수를 확인합니다. 한 번에 한 조건만 줄이고 실제 동작과 비용을 비교합니다. Cloth를 끄면 일반적으로 스키닝 중심의 모습으로 돌아가므로, 멀리 있는 캐릭터에서 끄는 방식도 외관을 확인한 뒤 판단합니다. 이 문서는 성능 측정값이나 특정 기기의 실행 보장을 제공하지 않습니다.

기본 설정의 정확한 의미는 [Cloth API](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/Cloth.html), 성능 확인 방법은 [성능 측정](../../../82_성능/성능측정.md)에서 이어 읽습니다.
