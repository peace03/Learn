# 16. 응용 과제와 복습

> 모르는 단어는 [전문 용어 전체 색인](../90_%EC%B0%B8%EA%B3%A0/%EC%9A%A9%EC%96%B4_%EC%82%AC%EC%A0%84.md)에서 영문·한글로 찾습니다. 이 장 맨 아래에는 등장 용어의 바로가기 목록이 있습니다.

## 응용은 비교 조건을 고정하는 연습이다

**비교 기준**은 바꾸기 전 상태, **통제 변수**는 비교 동안 같게 유지하는 조건입니다. 재질의 차이를 보려는데 빛과 카메라까지 함께 바꾸면 무엇 때문에 달라졌는지 알기 어렵습니다. 그래서 아래 과제는 한 번에 값 하나를 바꿉니다.

첫 과제의 모델을 찾기 어렵다면 Project 검색창에 `Lab_Material_Ball`을 입력합니다. 없거나 준비가 안 됐다면 같은 기본 Sphere 세 개로 진행할 수 있습니다. 각각 Position X를 `-2,0,2`, Y를 `0.5`로 두고 같은 크기를 사용합니다. 파일을 찾느라 핵심 실험을 중단하지 않아도 됩니다.

결과 기록은 “무엇을 바꿨나 → 무엇을 예상했나 → 실제로 무엇이 보이나 → 아직 확인하지 않은 것은 무엇인가” 순서로 씁니다. 남의 완성 화면과 비슷해 보이는 것보다 자기 설정의 결과를 설명할 수 있는지가 학습 기준입니다.

목표는 메뉴를 외우는 것이 아니라 **원하는 결과에 필요한 부품을 고르고, 맞게 연결하고, 확인하는 것**입니다. 아래 과제는 기존 기능을 조합합니다. 문서 작성 과정에서 만들어 둔 완성 씬은 아닙니다.

## 과제 1. 제품 사진관

**만들 것:** 같은 모델을 무광·금속·유광으로 비교하는 장면.

1. 02장의 실습 씬을 한 번 더 복제해 `_Study/Scenes/Study_Materials`로 저장합니다.
2. `Lab_Material_Ball.fbx` 또는 Cube 세 개를 배치합니다. 같은 모양과 크기를 사용합니다.
3. URP/Lit 재질 세 개를 새로 만들어 각각 연결합니다.
4. 첫 비교에서는 Metallic만 바꾸고 Smoothness는 고정합니다.
5. 다음 비교에서는 Metallic을 고정하고 Smoothness만 바꿉니다.
6. 동일 카메라·광원·Volume 아래에서 결과를 캡처하거나 숫자와 인상을 적습니다.

완료 기준: “더 반짝인다” 대신 “Smoothness를 올리니 하이라이트가 더 좁게 모였다”처럼 바꾼 값과 보이는 결과를 함께 설명합니다.

활용: 캐릭터 장비 재질 비교, 상점 아이템 미리보기, 모델 포트폴리오 촬영.

## 과제 2. 분위기 비교 버튼

**만들 것:** Warm/Cool 두 화면을 버튼으로 바꾸는 전시실.

1. 13장의 Posts·Selected Post·On Click을 연결합니다.
2. 버튼을 여러 번 눌러 처음 상태로 돌아오는지 확인합니다.
3. Game 해상도를 바꾸어도 버튼이 화면 밖으로 나가지 않는지 확인합니다.
4. 마우스 외에 키보드 선택과 제출도 확인하려면 UI Input Module의 Navigate·Submit 참조와 Button Navigation을 확인합니다.
5. 글자와 배경의 명암을 충분히 벌립니다. 색만 바뀌는 상태를 구분하기 어렵다면 버튼 이름·설명도 함께 제공합니다.

완료 기준: 클릭이 먹는 것, Volume 활성 상태가 바뀌는 것, 실제 색 변화가 보이는 것을 각각 확인합니다.

활용: 렌더링 전후 비교, 설정 화면, 다양한 시간대 연출의 시제품.

## 과제 3. 캐릭터 동작 검사대

**만들 것:** 한 번에 캐릭터 하나를 켜 걷기·달리기를 확인하는 장면.

1. Walk와 Runing을 같은 위치·비슷한 크기로 배치합니다.
2. 하나만 활성화합니다. 겹친 두 모델을 애니메이션 잔상으로 오해하지 않게 합니다.
3. 원본 모델의 Avatar·Controller·Motion 출처를 기록합니다.
4. 정면·측면·후면에서 발·무릎·팔꿈치·골반을 봅니다.
5. 최소 두 주기 이상 재생해 루프 경계와 Root 이동을 확인합니다.
6. Generic 결과와 Humanoid 리타기팅 결과를 구분해 기록합니다.

완료 기준: Preview만 확인하고 끝내지 않습니다. 씬 Play에서 대상 메시가 정상적으로 변형되는지 봅니다.

활용: AI 생성 캐릭터 검수, 다른 모델로 동작 옮기기, 애니메이션 납품 확인.

## 과제 4. 화면 품질과 속도 비교

**만들 것:** 품질 하나를 낮췄을 때 얻은 이득과 잃은 외관을 설명하는 보고.

1. 같은 카메라·동작·해상도를 정합니다.
2. 반사 Full/Half만 비교합니다.
3. 다음에는 반사를 원래 값으로 돌리고 먼지 양만 비교합니다.
4. 18장 방식으로 CPU/GPU 프레임 시간을 기록합니다.
5. 한 번 빨랐던 값 대신 여러 프레임의 경향을 봅니다.

완료 기준: “가벼워졌다”가 아니라 “같은 장면에서 반사면이 덜 선명해졌고 GPU 시간이 어느 정도 바뀌었다”처럼 측정 조건과 결과를 적습니다. 실제 측정 전에는 숫자를 채우지 않습니다.

## 변경
어떤 슬롯에 무엇을 연결하고 어떤 값을 바꿨는가?

## 예상과 실제
예상:
실제:

## 확인

- [ ] 씬 Play

## 복습 문제

| 문제 | 답의 핵심 |
|---|---|
| Scene을 복제했는데 원본 재질도 바뀐다. 왜인가? | 공용 Material 에셋을 공유 |
| 금속이 검다. Base Color만 바꾸면 될까? | 환경 반사·광원·Metallic·노출도 확인 |
| ORM은 어디에 꽂아야 하나? | 먼저 채널 뜻 확인. 현재 원본 R=AO, G=Roughness, B=Metallic |
| Volume 수치가 있는데 효과가 없다. | Override·카메라·레이어·Weight·다른 Volume |
| Scene 시점은 바뀌는데 Game이 그대로다. | 편집 시점과 게임 카메라 분리 |
| Humanoid인가를 파일 이름으로 알 수 있나? | Rig와 Avatar 유효성 확인 |
| 상태 진행 막대가 움직이면 애니메이션 검사가 끝났나? | 실제 뼈·스킨 메시·루프 확인 필요 |
| Extract 성공 로그가 외관 일치를 보장하나? | 파일·구조 조건과 시각 검증은 별개 |
| 스크립트 파일이 있는데 버튼이 동작하지 않는다. | 인스턴스 부착·On Click 연결·입력 체계 확인 |
| FPS만 비교하면 충분한가? | 프레임 시간·CPU/GPU·조건을 같이 봄 |

## 공부를 마쳤다고 볼 기준

- [ ] 용어를 설명하고 Inspector에서 그 항목을 찾을 수 있다.
- [ ] 모델 → 재질 → 조명 → 카메라 → 후처리 흐름을 말할 수 있다.
- [ ] 클립·Controller·Avatar의 차이를 설명할 수 있다.
- [ ] 어떤 조작이 씬만 바꾸고 어떤 조작이 공용 에셋까지 바꾸는지 안다.
- [ ] 문제 하나를 재현하고 변수 하나씩 바꾸며 원인을 좁힌다.
- [ ] 확인하지 않은 결과를 성공이라고 적지 않는다.
