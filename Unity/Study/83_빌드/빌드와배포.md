# 빌드와 배포

[전체 주제 목차](../README.md) · [전체 용어 사전](../90_용어사전/README.md)

**빌드**는 편집기 밖에서 실행할 프로그램을 만드는 일, **Player**는 그 실행 환경입니다. **플랫폼**은 Windows처럼 실행할 환경, **Development Build**는 측정·진단을 돕는 개발용 빌드입니다. Editor에서만 쓰는 코드는 Player에 없는 기능을 참조할 수 있으므로 분리해야 합니다.

## 빌드: 편집기 밖에서 실행할 프로그램 만들기

프로젝트를 Play하는 것과 실행 파일을 만드는 것은 다릅니다. 현재 자료는 **빌드 통과를 확인한 상태가 아닙니다.** 특히 다음 두 사실부터 알아야 합니다.

1. 저장된 기본 Build Scene 목록에는 `SampleScene`만 켜져 있습니다.
2. `05.Editor` 아래와 `Lab_Varco3D` 아래에 `UnityEditor`를 직접 사용하는 코드가 있고, 대부분 정확한 `Editor` 폴더·Editor 전용 asmdef·`UNITY_EDITOR` 조건으로 분리되지 않았습니다.

`05.Editor`라는 이름만으로 Editor 전용 컴파일이 되지 않습니다. Unity의 특수 폴더는 정확히 `Editor`입니다. [특수 폴더 규칙](https://docs.unity3d.com/6000.0/Documentation/Manual/SpecialFolders.html).

## 먼저 해결해야 할 코드 경계

배포 작업을 따로 할 때 선택 가능한 원칙은 다음과 같습니다.

- 순수 Editor 파일은 정확한 `Editor` 폴더 또는 Editor만 포함하는 asmdef로 분리.
- 공용 파일 안의 일부 Editor 코드만 제외해야 하면 적절한 `#if UNITY_EDITOR` 경계 사용.
- Editor 타입을 런타임 코드가 참조하지 않도록 의존 방향 확인.

패키지 Bridge는 이미 `VARCO3DBridge.Editor.asmdef`의 includePlatforms가 Editor입니다. Assets의 도구 코드와 같은 상태로 묶어서 설명하면 안 됩니다. 폴더 이동은 `.meta`와 참조를 유지하도록 Unity Project 창에서 수행하고, 이동 후 Editor 컴파일과 Player 빌드를 따로 확인합니다. 이 문서 작업에서는 이러한 이동·수정을 수행하지 않았습니다.

## 빌드 준비가 된 뒤의 클릭 순서

1. 실습 씬을 저장하고 `File > Build Profiles`를 엽니다.
2. Windows 등 목표 플랫폼 프로필을 고릅니다. 필요한 Build Support가 없다면 Unity Hub의 해당 Editor 설치에서 모듈을 추가해야 합니다.
3. 실제 사용할 프로필의 **Scene List**를 엽니다. 공유 목록을 쓰는지 프로필별 Override를 쓰는지도 확인합니다.
4. `Add Open Scenes` 또는 Project의 씬 파일 드래그로 실행할 실습 씬을 넣습니다.
5. 켜진 씬 중 처음 실행할 씬을 맨 위로 옮깁니다. 기본 SampleScene만 남아 있지 않은지 확인합니다.
6. 처음 검증은 `Development Build`를 사용하고, 필요하면 `Autoconnect Profiler`를 선택합니다.
7. `Build` 또는 `Build And Run`을 누르고 `Builds/Windows` 같은 **Assets 밖의 출력 폴더**를 선택합니다.
8. Console의 첫 빌드 오류를 확인합니다. 성공 후 실행 파일에서 카메라·UI·애니메이션·재질을 다시 확인합니다.

Build Profiles의 메뉴 목적은 [Unity 공식 설명](https://docs.unity3d.com/6000.0/Documentation/Manual/build-profiles.html)을 참고합니다. 활성 플랫폼·실제 Build Profile은 이번 작업에서 Editor로 조회하지 않았습니다.

## 저장·이동·공유

다른 PC로 프로젝트를 옮길 때 기본 원본 묶음은 `Assets + Packages + ProjectSettings`입니다. 에셋의 `.meta`를 함께 보존합니다. `Library`는 일반적으로 재생성할 수 있는 캐시이지만, 패키지 다운로드·임포트에 다시 시간이 필요합니다.

현재 Bridge manifest에 외부 절대경로가 남아 있으므로 다른 PC에서는 embedded 패키지 인식 상태까지 확인합니다. `Packages/packages-lock.json`을 보고 모든 환경이 자동으로 재현된다고 단정하지 않습니다.

실행 파일만 전달할 때도 `.exe` 하나만 떼지 말고 Unity가 만든 해당 빌드 출력의 필요한 파일·폴더를 함께 전달합니다.

## 단계별 확인표

| 단계 | 통과 의미 | 대신 증명하지 못하는 것 |
|---|---|---|
| C# 컴파일 | 소스가 현재 대상에서 컴파일됨 | 임포트·재생·외관 |
| 에셋 임포트 | Unity가 데이터를 읽음 | 원하는 재질·움직임 |
| Preview | 선택한 에셋의 미리보기 | 실제 씬의 연결과 입력 |
| 씬 Play | Editor에서 해당 흐름 실행 | Player 빌드 성공 |
| Player 빌드 | 대상 실행 파일 생성 | 해당 PC에서의 정상 동작·성능 |
| 실행 파일 검증 | 시험한 조건에서 실행 확인 | 모든 플랫폼·모든 입력 |
