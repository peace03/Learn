# PBR·텍스처·재질

> 모르는 단어는 [전문 용어 전체 색인](../../90_용어사전/README.md)에서 영문·한글로 찾습니다. 이 장 맨 아래에는 등장 용어의 바로가기 목록이 있습니다.

## 빛이 닿은 뒤 어느 방향으로 나가는가

준비 C의 픽셀·RGB·채널·빛, 준비 B의 법선·UV가 선수 개념입니다. **PBR**은 Physically Based Rendering의 약자입니다. 실제 빛의 성질을 기준으로 표면을 계산합니다. 입사한 빛보다 반사되는 빛이 임의로 커지지 않도록 하는 **에너지 보존** 같은 제약을 사용합니다. Emission은 별도의 발광 입력입니다.

비금속에서는 표면에서 반사되는 빛과 내부로 들어갔다 흩어져 나오는 빛을 나누어 생각합니다. 후자의 근사가 **확산 반사**, 방향이 모이는 성분이 **정반사**입니다. 금속은 가시광에서 주로 표면 반사가 중요하고 Base Color가 그 반사의 색에 관여합니다. 같은 파란 Base Color라도 Metallic을 바꾸면 보이는 결과가 달라지는 이유입니다.

표면을 아주 작게 보면 여러 방향의 미세한 면이 있다고 모델링할 수 있습니다. 미세한 면의 방향이 다양할수록 하이라이트가 퍼집니다. Roughness는 이 거칠기, Smoothness는 반대 방향의 매끈함을 조절합니다. 이는 실제 메시를 거칠게 깎는 기능과 다릅니다.

Normal Map은 색 그림처럼 보이지만 작은 표면 방향을 숫자로 담습니다. **탄젠트 공간**은 각 표면의 가로·세로·법선 방향을 기준으로 삼은 좌표계입니다. 이를 실제 물체 방향으로 옮겨 조명을 계산하므로 탄젠트·법선·UV가 맞아야 합니다. 파란색 그림을 Base Map에 넣는 것과 Normal 슬롯에 넣는 것은 의미가 다릅니다.

## 숫자로 채널을 따라가 보기

ORM 한 픽셀 값이 `(R=0.8, G=0.2, B=1)`이면 이 입력에서는 차폐 0.8, 거칠기 0.2, 금속성 1입니다. Smoothness는 `1-0.2=0.8`로 옮길 수 있습니다. URP/Lit Metallic Map R에는 **1**, Smoothness A에는 **0.8**이 필요합니다. ORM의 R=0.8을 그대로 금속성으로 읽으면 다른 표면을 계산하게 됩니다.

**슬롯을 채우는 행위**와 **그 숫자의 뜻을 맞추는 행위**를 모두 해야 합니다. 아래 실습에서 Base Map 색상을 흰색으로 두는 이유도 같습니다. 색상과 이미지 색이 곱해지므로, 흰색 `(1,1,1)`은 원본 이미지 색을 추가로 바꾸지 않습니다.

## 표면을 만드는 네 가지

**Mesh**는 모양, **Texture**는 그림 또는 숫자 지도, **Material**은 표면 설정 묶음, **Shader**는 그 설정을 읽어 픽셀 색을 계산하는 규칙입니다.

종이로 만든 구에 무늬를 붙인다고 금속이 되지는 않습니다. 금속처럼 보이려면 빛을 반사하는 방식도 달라야 합니다. **PBR**은 빛과 표면의 관계를 물리적인 성질에 맞춰 근사하는 방식입니다.

## 기본 속성

| 속성 | 쉬운 뜻 | 정확히 알아둘 것 |
|---|---|---|
| Base Map / Base Color | 표면의 기본 색과 무늬 | 조명·노출을 포함한 최종 화면 색이 아님 |
| Metallic | 금속 정도 | 순수 금속과 비금속은 빛 반사 방식이 다름. 혼합·오염 영역에는 중간값 가능 |
| Smoothness | 매끈한 정도 | 높을수록 반사가 모이고 낮을수록 퍼짐 |
| Roughness | 거친 정도 | 일반적인 변환에서 `Smoothness = 1 - Roughness` |
| Normal Map | 작은 요철의 방향 | 주로 빛 계산의 방향을 바꿈. 모델 외곽선·충돌 모양을 직접 늘리지 않음 |
| Occlusion / AO | 틈에 들어오기 어려운 간접광 | 실제 광원의 그림자와 역할이 다름 |
| Emission | 스스로 밝게 보이는 색 | 그 자체만으로 주변에 실시간 광원을 생성하지 않음 |
| Alpha | 불투명도에 쓸 값 | 셰이더의 Surface Type·Alpha Clipping 설정에 따라 처리 방식이 다름 |

`URP/Lit`의 슬롯과 속성은 [Unity Lit 문서](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/lit-shader.html)에서도 확인할 수 있습니다.

## UV: 그림을 붙이는 주소

UV는 3D 표면의 각 지점이 2D 그림의 어디를 읽을지 정하는 좌표입니다. U는 가로, V는 세로입니다. 상자를 펼친 종이 도안과 비슷합니다. `Tiling`은 그림을 반복하는 횟수, `Offset`은 읽을 위치를 미는 값입니다.

그림이 늘어나면 텍스처 해상도만 올리기 전에 UV를 봅니다. 서로 다른 면이 같은 그림 위치를 공유할 수 있으며, UV 경계의 이음새와 메시가 실제로 찢어진 것은 다릅니다.

## sRGB와 Linear

색상 이미지는 보통 사람이 보기 좋은 밝기 분포인 sRGB로 저장합니다. 금속성·거칠기 같은 데이터 지도는 숫자를 그대로 읽어야 하므로 Linear 데이터로 취급합니다.

Project의 Texture를 선택해 Inspector에서 확인합니다.

- Base Color: 보통 `sRGB (Color Texture)` 켬.
- ORM·Mask 같은 수치 지도: 보통 sRGB 끔.
- Normal: `Texture Type = Normal map`으로 지정하고 `Apply`.

프로젝트의 Color Space는 Linear로 저장되어 있습니다. 프로젝트의 계산 방식과 개별 텍스처의 sRGB 여부는 서로 다른 설정입니다.

## 이 프로젝트의 핵심 사례: ORM 채널

PNG 한 장은 R·G·B·A라는 여러 숫자 통로를 가질 수 있습니다. 채널마다 다른 성질을 저장하면 여러 지도를 한 장에 담을 수 있습니다.

원본 Walk USDZ 안의 `model.usda`를 읽어 확인한 연결:

| 채널 | 원본 `mat_3_orm.png`의 뜻 | URP/Lit에서 직접 꽂았을 때 |
|---|---|---|
| R | Occlusion | Metallic Map의 금속성 R로 읽힐 수 있음 |
| G | Roughness | Occlusion Map의 차폐 G로 읽힘 |
| B | Metallic | 금속성 값으로 자동 재배치되지 않음 |
| A | 원본 표면 연결에서 사용하지 않음 | Metallic Map의 Smoothness 원천으로 사용될 수 있음 |

`Varco3DExtractTool.ApplyTextures()`는 ORM을 `_MetallicGlossMap`과 `_OcclusionMap`에 그대로 넣습니다. **채널 재배치를 하지 않습니다.** 따라서 연결 완료와 재질 정확성은 다릅니다. 이는 파일명만 보고 추측한 것이 아니라 USD 표면 연결과 로컬 URP `LitInput.hlsl`을 대조한 결과입니다.

정확히 옮기는 원리:

```text
URP Metallic R  ← 원본 B
URP Smoothness A ← 1 - 원본 G
URP Occlusion G ← 원본 R
```

색상 편집 도구로 새 지도를 만들거나, Shader Graph에서 채널을 나누어 연결할 수 있습니다. 원본 ORM을 덮어쓰지 않습니다. 아래 입문 실습은 우선 Base와 Normal만 연결해 이 문제를 분리합니다.

## 실습: 로봇 재질을 직접 연결한다

1. Project의 `_Study/Materials` 빈 곳 우클릭 → `Create > Material`. 이름을 `Study_Robot`으로 지정합니다.
2. Inspector의 `Shader`에서 `Universal Render Pipeline > Lit`을 선택합니다.
3. `Assets/VARCO_Converted/Streetwear Robot_Walk/Textures`를 엽니다.
4. `mat_3_base_color.png`를 재질 Inspector의 **Base Map 왼쪽 텍스처 칸**으로 드래그합니다. 옆 색상은 우선 흰색으로 둡니다.
5. `mat_3_normal.png`를 클릭해 `Texture Type = Normal map`을 확인하고, 필요하면 바꾼 뒤 `Apply`합니다. 원본 설정을 유지하려면 먼저 텍스처도 복제합니다.
6. 재질을 다시 클릭하고 Normal Map 슬롯에 Normal 텍스처를 드래그합니다.
7. Metallic Map·Occlusion Map은 비워 둡니다. Metallic `0`, Smoothness `0.4`로 비교 기준을 만듭니다. 이 값은 원본을 재현한 정답이 아닙니다.
8. Hierarchy의 Walk 아래 `mesh_0` 등 Skinned Mesh Renderer가 있는 물체를 선택합니다.
9. `Study_Robot.mat`을 Renderer > Materials의 해당 Element에 드래그합니다. 여러 슬롯이면 역할을 먼저 확인합니다.
10. Game에서 비교합니다. Normal 강도를 0과 1로 바꾸고 조명 아래 표면 차이를 봅니다. 실루엣은 거의 그대로여야 합니다.

재질 변경은 씬 저장과 별도로 에셋에 남습니다. 본 실습에서 생성한 `.mat`을 쓰는 이유입니다.

## 조금 더 깊이: 왜 금속이 검게 보일까

금속은 주변 환경의 반사를 크게 보여 줍니다. 반사할 환경이 빈약하면 Metallic을 올려도 기대한 금속 느낌이 나지 않습니다. Base Color만 밝게 만드는 대신 조명·Reflection Probe·환경을 확인합니다.

법선과 빛 방향의 내적 `N·L`은 두 방향이 얼마나 마주 보는지 나타냅니다. 표면이 빛을 정면으로 받으면 값이 크고 옆으로 누우면 작습니다. 실제 Lit 셰이더는 이보다 복잡한 반사 계산을 하지만, “방향이 표면 밝기를 바꾼다”는 출발점은 같습니다.

**확인 질문:** ORM의 R을 Metallic에 넣으면 왜 틀릴 수 있는가? Normal Map을 바꾸면 Collider도 울퉁불퉁해지는가?

**답:** 그 R은 원본에서 AO였기 때문입니다. Normal Map은 물리 충돌 모양을 바꾸지 않습니다.
