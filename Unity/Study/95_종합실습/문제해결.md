# 문제 해결 사전

> 모르는 단어는 [전문 용어 전체 색인](../90_용어사전/README.md)에서 영문·한글로 찾습니다. 이 장 맨 아래에는 등장 용어의 바로가기 목록이 있습니다.

## 오류 글을 읽는 첫 순서

**오류, Error**는 작업을 정상 완료하지 못한 상황, **경고, Warning**는 주의할 조건, **로그, Log**는 프로그램 기록입니다. 경고가 항상 실패는 아니고, 마지막 성공 로그가 전체 성공은 아닙니다. **재현**은 같은 조건에서 같은 문제를 다시 만드는 일입니다.

`Window > General > Console`에서 빨간 항목 하나를 클릭하면 아래에 상세 설명과 호출 경로가 나타납니다. 그 경로 목록인 **스택 트레이스**에서 프로젝트 파일명과 줄 번호를 찾습니다. 더블클릭은 연결된 코드 편집기를 열 수 있습니다. 글을 복사해 실습 기록에 붙이고 바로 앞에서 바꾼 대상도 적습니다.

컴파일 오류는 코드 준비 단계, 임포트 오류는 파일 읽기 단계, 실행 중 예외는 동작 중 잘못된 조건입니다. **managed**는 C# 관리 실행 환경 쪽, **native**는 엔진·플러그인 등의 기계 실행 코드 쪽을 뜻합니다. Editor 종료를 전부 C# 문법 오류라고 부르면 원인을 잘못 찾을 수 있습니다.

학습한 내용을 되돌려 비교할 때도 원본 변환 버튼을 계속 누르지 않습니다. 아래 표에서 가장 앞선 실패 단계를 하나씩 확인하고, 수정 뒤 **같은 조건**으로 다시 봅니다.

먼저 **대상·증상·직전에 바꾼 것**을 적습니다. Console의 첫 오류와 그 오류가 가리키는 파일을 읽습니다. 뒤에 쌓인 메시지를 전부 다른 원인으로 보지 않습니다.

## 1. 분홍색과 흰색은 다른 증상이다

분홍색은 렌더 파이프라인에 맞지 않는 Shader 또는 셰이더 문제를 우선 봅니다. 물체를 선택해 자식 Renderer > Materials > 실제 `.mat` > Shader로 들어갑니다. 새 URP/Lit 재질로 바꿔 비교하면 범위를 좁힐 수 있습니다.

흰색은 정상 셰이더라도 Base Map이 비었거나, 매우 밝은 조명·Emission·후처리가 색을 덮는 경우가 있습니다. [PBR·텍스처·재질 문서](../20_재질과셰이더/01_재질/재질과텍스처.md) 방식으로 새 재질에 Base Map만 넣고 비교합니다. 원본을 무작정 재추출하지 않습니다.

## 2. ORM을 넣었는데 플라스틱처럼 보인다

현재 Walk 원본은 R=AO, G=Roughness, B=Metallic입니다. 변환기는 이를 URP 슬롯에 그대로 연결합니다. [PBR·텍스처·재질 문서](../20_재질과셰이더/01_재질/재질과텍스처.md)의 채널 표와 [Shader Graph](../20_재질과셰이더/02_ShaderGraph/ShaderGraph.md)의 Split 실습으로 확인합니다. PNG 확장자가 같아도 채널 약속은 같지 않습니다.

## 3. 오브젝트가 사라졌다

1. Hierarchy에서 이름을 검색합니다.
2. 오브젝트와 모든 부모의 활성 체크를 봅니다.
3. Transform Scale이 0인지 확인합니다. Transform 오버레이에서 Copy 전 Paste를 했다면 특히 봅니다.
4. Renderer 활성과 재질 Alpha를 확인합니다.
5. `F`로 찾은 뒤 Game 카메라가 같은 방향을 보는지 확인합니다.
6. Culling Mask·Near/Far·Scene Visibility 숨김 상태를 확인합니다.

주 씬의 Runing과 여신상은 저장 상태에서 꺼져 있습니다. 숨겨진 것을 무조건 임포트 실패로 판단하지 않습니다.

## 4. 애니메이션이 멈추거나 뒤틀린다

1. Play인지, Animator 컴포넌트가 켜졌는지 확인합니다.
2. Controller가 연결되고 기본 상태의 Motion이 비어 있지 않은지 봅니다.
3. 클립 Preview에서 뼈가 움직이는지 봅니다.
4. Generic이면 Animator 루트에서 시작하는 뼈 경로가 클립 바인딩과 같은지 확인합니다.
5. Humanoid면 모델 자신의 Avatar, 필수 매핑, T-Pose를 확인합니다.
6. Root Motion·Bake Into Pose·Loop 설정을 확인합니다.
7. 실제 Skinned Mesh Renderer의 뼈 참조·Bind Pose·Weight 문제인지 분리합니다.

현재 변환 폴더의 Original/RetargetClean `.anim`은 Legacy입니다. 일반 Animator 상태에는 10장처럼 FBX 내부 클립을 사용합니다.

`Copy From Other Avatar` 불일치는 단순 이름 유사성으로 해결하지 않습니다. 부모 경로가 다르면 각 모델에서 Avatar를 만들고 Humanoid 클립을 옮기는 방향을 검토합니다.

## 5. Bridge 연결 또는 변환 실패

| 메시지·상황 | 뜻 | 할 일 |
|---|---|---|
| port 5326 사용 중 | 다른 실행 흐름이 같은 포트를 점유할 가능성 | 여러 Unity 인스턴스의 Connect 상태 확인. 무작정 다른 프로세스를 종료하지 않음 |
| Unity에 모델이 안 생김 | 통신·다운로드·임포트·배치 중 어느 단계인지 불명 | Console에서 마지막 성공 단계 찾기 |
| `FBX Exporter Missing` | Exporter 타입·함수를 못 찾음 | Package Manager에서 FBX Exporter 상태와 컴파일 오류 확인 |
| `binary USD/USDC instead of USDA text` | 현재 전용 변환기가 읽지 않는 내부 형식 | Bridge 임포트 가능 여부와 별도로 구분. 확장자만 바꾸지 않음 |
| `def SkelAnimation was not found` | 필요한 애니메이션 텍스트 블록 없음 | 정적 모델인지·입력 형식인지 확인 |
| `Bone not found` / `No USD animation joints matched` | 선택 계층과 애니메이션 뼈가 맞지 않음 | 맞는 원본·루트 선택, 부모 컨테이너 포함 여부 확인 |
| `Root Y curve was not found` | 해당 보정 곡선이 없음 | 전체 변환 실패와 구분하고 실제 동작 확인 |
| `Retarget Ready: False` | 검사한 조건 일부 미충족 | Mapping·Avatar·Animation 항목을 각각 확인 |

재시도 전에 기존 출력의 백업을 확인합니다. 같은 파일을 지우고 재생성하는 작업을 원인 파악 없이 반복하지 않습니다.

Unity가 임포트 중 종료되었다면 managed C# 컴파일 오류와 native 임포터 충돌을 구별합니다. 버전·대상 파일·로그의 마지막 단계를 보존하고 **복제 프로젝트**에서 해당 입력만 분리해 조사합니다. 캐시 삭제만으로 원인을 해결했다고 단정하지 않습니다.

## 6. 클릭해도 아무 일도 없다

Game 창에 마우스가 들어가 있는지 확인합니다. 버튼의 Interactable, On Click 대상·함수, Canvas의 Graphic Raycaster, 활성 EventSystem, Input System UI Input Module을 봅니다.

전체 화면 Image가 Raycast Target을 켜고 위에 놓이면 버튼이 가려질 수 있습니다. 화면에서 투명해 보여도 입력을 가로막을 수 있습니다. Fade Image는 의도에 맞게 Raycast Target을 끕니다.

## 7. 스크립트를 붙일 수 없다

먼저 Console 오류를 해결해야 합니다. 그다음 파일명과 MonoBehaviour 클래스 이름을 봅니다. 현재 `Lab_DecalScaler.cs`의 클래스는 `DecalScaler`여서 불일치가 있습니다. 실제 부착 가능 여부는 Editor에서 확인해야 합니다. 입문 데칼 실습은 이 스크립트 없이 진행합니다.

프로젝트 문서 작업은 문제를 기록하는 작업입니다. 여기에 적힌 코드나 설정을 자동으로 수정한 것은 아닙니다.

## 재현 기록 예시

```text
대상: Study_Lab / Study_CoolVolume
증상: Next 클릭 때 활성은 바뀌지만 색은 같음
변경: Button.OnClick → NextPost 연결
관찰: selectedPost 0→1, Console 오류 없음
다음 검사: Cool Profile의 Temperature Override와 카메라 Volume Layer Mask
```

“버튼 고장”이라고 시작해도 활성 상태가 바뀐다면 입력·함수 연결 뒤의 단계로 조사 범위를 좁힐 수 있습니다.
