# UI 연결 실습

> 모르는 단어는 [전문 용어 전체 색인](../90_용어사전/README.md)에서 영문·한글로 찾습니다. 이 장 맨 아래에는 등장 용어의 바로가기 목록이 있습니다.

## 클릭 한 번이 화면을 바꾸는 경로

[C#과 실행 흐름 문서](../80_프로그래밍/CSharp와실행흐름.md)의 참조·인스턴스·배열·함수를 먼저 읽고 [Volume 후처리 문서](../50_시각효과/01_후처리/Volume.md)의 Profile 복제를 마칩니다. **UI**는 사용자에게 정보를 보여 주고 조작을 받는 화면입니다. 이 장은 Canvas에 버튼을 만드는 **uGUI** 방식을 사용합니다.

```text
마우스 클릭 → 입력 모듈 → EventSystem → Button의 On Click
→ 씬의 Lab_PostSelection.NextPost 호출 → 다음 Volume 물체 활성
→ 카메라가 새 Profile 값으로 화면을 그림
```

**이벤트**는 “이 일이 생겼다”는 알림, **콜백**은 그때 다른 시스템이 불러 주는 함수입니다. On Click에는 호출할 컴포넌트가 붙은 실제 물체와 함수 이름을 함께 연결합니다. 스크립트 설계 파일만 넣으면 어느 인스턴스를 실행할지 정할 수 없습니다.

Rect Transform의 **Anchor**는 부모 사각형의 어느 위치에 붙을지, **Pivot**은 자기 사각형의 기준점입니다. 가운데 Anchor와 Pivot `(0.5,0.5)`면 Pos X/Y는 대체로 가운데에서 떨어진 위치를 읽기 쉽습니다. **Stretch**는 부모 범위에 맞춰 늘어나는 배치입니다.

Anchor Presets에서 가운데를 고른 뒤 Anchor Min/Max와 Pivot이 각각 `(0.5,0.5)`인지 확인합니다. 다르면 값을 직접 넣은 뒤 아래 위치·크기를 입력합니다. **Reference Resolution**은 UI 크기 계산의 기준 화면이고 실제 모니터 해상도를 강제로 바꾸는 설정이 아닙니다. 화면 비율을 바꿔 재확인해야 합니다.

목표: 버튼을 눌러 화면 분위기를 바꿉니다. `Lab_PostSelection`을 실제 씬에 연결하며 오브젝트 참조·배열·이벤트를 함께 배웁니다.

**현재 상태:** `Lab_Canvas`의 6개 스크립트 GUID는 조사한 `.unity`와 `.prefab`에서 사용되지 않았습니다. 기존 `ProgressBar` 모양이 있다는 사실만으로 진행률을 계산하는 기능이 있다고 볼 수 없습니다. 이 장은 독자가 직접 새로 연결하는 실습입니다.

## 먼저 알아둘 부품

| 부품 | 역할 |
|---|---|
| Canvas | uGUI를 그리는 판 |
| Rect Transform | UI의 위치·크기·기준점 |
| Anchor | 부모 크기가 바뀔 때 붙잡을 위치 |
| Canvas Scaler | 화면 크기에 맞춘 UI 크기 규칙 |
| Graphic Raycaster | UI에 포인터가 닿는지 판정 |
| EventSystem | 클릭·선택 같은 UI 입력 전달 |
| Input System UI Input Module | 새 Input System을 UI에 연결 |
| Button > On Click() | 클릭할 때 호출할 함수 목록 |

Canvas와 EventSystem은 다른 오브젝트입니다. 버튼 그림만 있어도 입력을 전달하는 구성이 빠지면 작동하지 않습니다.

## 1. 바꿔 볼 Volume 두 개

1. `Study_Lab`을 열고 Play를 끕니다.
2. [Volume 후처리 문서](../50_시각효과/01_후처리/Volume.md)의 `Study_Lab_Profile`을 복제해 `_Study/Profiles/Study_Warm`, `Study_Cool`을 만듭니다.
3. 각 Profile의 White Balance > Temperature Override를 켜고 Warm은 `20`, Cool은 `-20`으로 둡니다.
4. Hierarchy 빈 곳 우클릭 → `Create Empty` → 이름 `Study_WarmVolume`.
5. Inspector > `Add Component`에서 `Volume`을 추가합니다. Mode는 Global, Weight는 1로 둡니다.
6. `Study_Warm` 프로필을 Profile 슬롯에 드래그합니다.
7. 같은 방법으로 `Study_CoolVolume`을 만들고 `Study_Cool`을 연결합니다.
8. 기존 `Lab_Studio_Env/Lighting/Volume Profile` 오브젝트를 **복사 씬에서만** 비활성화합니다. 두 실습 Volume과 값이 섞이는 일을 줄입니다.
9. WarmVolume은 켜고 CoolVolume은 끕니다. 둘은 비활성 컨테이너의 자식으로 만들지 않습니다.

## 2. 전환 담당 오브젝트

1. 빈 GameObject를 만들고 이름을 `Study_PostSwitcher`로 지정합니다.
2. Project의 `Lab_PostSelection.cs`를 이 오브젝트의 Inspector 빈 공간으로 드래그합니다.
3. Inspector의 `Posts` 배열을 펼쳐 Size를 `2`로 지정합니다.
4. **Hierarchy의** WarmVolume을 `Element 0`, CoolVolume을 `Element 1`에 드래그합니다.
5. `Selected Post`를 `0`으로 맞춥니다.

Posts에는 Profile `.asset`이 아니라 **Volume이 붙은 GameObject**를 넣습니다. 스크립트가 호출하는 것은 `GameObject.SetActive()`이기 때문입니다. 배열에 None이 있거나 번호가 0~1 밖이면 현재 코드에서는 오류가 날 수 있습니다.

## 3. 버튼 두 개

1. `GameObject > UI > Canvas`로 새 Canvas를 만들고 이름을 `Study_Canvas`로 지정합니다.
2. Canvas > Render Mode를 `Screen Space - Overlay`로 확인합니다.
3. Canvas Scaler > UI Scale Mode를 `Scale With Screen Size`, Reference Resolution을 `(1920,1080)`으로 둡니다.
4. Hierarchy에서 Study_Canvas를 우클릭 → `UI > Button - TextMeshPro`. 이름을 `NextButton`으로 지정합니다. TMP Essentials 안내가 나오면 필요한 기본 리소스를 프로젝트로 가져오는 버튼을 선택합니다.
5. Rect Transform의 Anchor Presets에서 가운데 기준을 고릅니다. Pos X `140`, Pos Y `-400`, Width `240`, Height `80`을 입력합니다.
6. 버튼의 자식 Text(TMP)를 선택해 글자를 `Next`로 바꿉니다. 영문으로 먼저 입력하면 한글 폰트 누락 문제와 기능 연결 문제를 분리할 수 있습니다.
7. 버튼을 `Ctrl+D`로 복제해 `PreviousButton`, Pos X `-140`, 글자 `Previous`로 만듭니다.

버튼이 기존 UI에 가리면 Study_Canvas의 Sort Order를 기존 것보다 높게 두거나, 복사 씬의 기존 Canvas를 잠시 끕니다. 화면 비율에 따라 위치를 조절하되 Game 탭에서 실제로 확인합니다.

## 4. On Click에 함수 연결

1. `NextButton`을 선택하고 Inspector > Button > `On Click()`을 펼칩니다.
2. `+`를 누릅니다.
3. 빈 Object 슬롯에 **Hierarchy의 `Study_PostSwitcher`**를 드래그합니다. `.cs` 파일 자체를 넣지 않습니다.
4. 오른쪽 `No Function`을 눌러 `Lab_PostSelection > NextPost()`를 고릅니다.
5. `PreviousButton`에도 같은 오브젝트를 넣고 `PreviousPost()`를 고릅니다.

호출 대상은 클래스 설계도가 아니라 씬에 붙어 있는 실제 컴포넌트입니다. 함수가 목록에 없다면 컴파일 오류, public 여부, 대상 오브젝트에 컴포넌트가 있는지를 봅니다.

## 5. 입력과 결과 확인

1. Hierarchy에 활성 `EventSystem`이 하나 있는지 확인합니다. 없으면 `GameObject > UI > Event System`으로 만듭니다.
2. 프로젝트는 새 Input System을 사용합니다. EventSystem에 `Input System UI Input Module`이 있는지 확인합니다. 구형 Standalone Input Module만 있다면 Inspector의 교체 안내를 사용하거나 기존 모듈을 제거하고 새 모듈을 추가합니다.
3. UI Input Module의 Actions Asset·Point·Left Click 등 기본 액션 참조가 비어 있지 않은지 확인합니다. `Assign Default Actions` 버튼이 표시되면 기본 UI 동작을 연결할 수 있습니다.
4. Play를 켜고 Next → Next를 누릅니다. 차가운 화면 → 따뜻한 화면으로 돌아오는지 확인합니다.
5. Hierarchy에서 Warm/Cool의 활성 체크가 번갈아 바뀌는지도 함께 봅니다.
6. Previous도 확인합니다. 두 방향 모두 반복해서 오류가 없어야 합니다.

색이 안 바뀌어도 오브젝트 활성 상태가 바뀐다면 버튼 연결은 동작한 것입니다. 그다음 문제는 Volume·카메라·Override 쪽으로 좁힙니다.

## 추가 실습: 검은 화면에서 나타나기

1. Study_Canvas 우클릭 → `UI > Image` → 이름 `Study_Fade`.
2. Rect Transform Anchor Presets에서 가로·세로 Stretch를 선택하고 Left·Right·Top·Bottom을 모두 0으로 맞춥니다.
3. Image Color를 검정으로, Raycast Target을 꺼 둡니다. 화면을 덮는 동안 버튼 입력을 가로막지 않게 하는 설정입니다.
4. 이 Image 오브젝트에 `Lab_FadeFromBlack.cs`를 드래그해 붙입니다.
5. Fade In Duration을 `1`로 지정합니다. 해당 Image를 Canvas의 마지막 자식으로 두어 위에 그려지게 합니다.
6. Play 첫 시작에서 검정이 사라지는지 확인합니다. 이 코드는 재활성화 반복 재생용이 아니라는 점은 [C#과 실행 흐름 문서](../80_프로그래밍/CSharp와실행흐름.md)에서 설명했습니다.

## 종료 버튼의 실제 행동

`Lab_Exit.Btn_Close()`는 먼저 `Btn_Ads()`로 작성자의 ArtStation URL을 브라우저에 열고 `Application.Quit()`를 호출합니다. 일반적인 순수 종료 함수라고 이름만 보고 연결하지 않습니다. Editor에서는 Application.Quit가 Play 종료 버튼을 대신하지 않습니다.

**확인 질문:** On Click 슬롯에는 왜 `.cs` 대신 씬의 오브젝트를 넣는가? Posts 0이 Cool인데 Selected Post=0, Warm만 켠 상태로 시작하면 무엇이 틀릴까?

**답:** 실행할 인스턴스가 필요합니다. 선택 번호와 실제 활성 오브젝트가 어긋나 전환 상태가 꼬일 수 있습니다.
